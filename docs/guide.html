阅读与练习指南

运行环境、练习方法与验证边界。

这份教程适合已经能阅读简单 Haskell 程序、想进一步理解「怎样把正确性条件交给工具检查」的读者。你不必先学会依赖类型，也不必先成为逻辑学专家。第 2 章会补上需要的逻辑知识。

译者说明：本页是中文译本新增的阅读辅助，不属于英文原著。教程正文中的代码和练习保留上游原貌；其中有些代码就是要让验证器报错。

怎样安排阅读顺序#

第一次阅读，建议按章节顺序走。每一部分都在回答一个具体问题：

部分 要解决的问题 读完后应该能做什么
第 1–5 章：精化类型 普通类型之外，还能表达什么？ 读懂精化类型，给函数写前置条件、后置条件和数据结构不变量
第 6–8 章：度量函数 验证器怎样理解列表等递归结构？ 描述是否为空、长度是多少、包含哪些元素
第 9–12 章：案例 这些工具怎样一起工作？ 跟着队列、映射、字节与 AVL 树，理解较大程序的规格与证明边界

如果你只想先建立直觉，可以读第 1、3 章，再返回第 2 章。看到不熟悉的术语时，打开术语表；需要核对措辞时，每章标题下都有英文原文入口。

运行前，先确认环境#

阅读网页不需要安装 Haskell。 下载仓库后，直接打开 docs/index.html 就能阅读，章节导航、搜索、主题切换均在浏览器本地工作。网页里的代码块用于阅读和复制，不是在线编译器。

实际做练习时，需要分别确认以下几件事：

  1. GHC 与 LiquidHaskell 的版本是否配套。 LiquidHaskell 作为 GHC 插件工作，不能假设任意 GHC 版本都兼容。先查官方安装页列出的组合，再选对应的示例项目。
  2. SMT 求解器是否可用。 官方安装页推荐 Z3，并要求求解器程序可以从 PATH 找到。安装 GHC 或 HLS，并不等于已经安装求解器。
  3. 项目是否真正启用了插件。 依赖声明、模块中的插件选项以及相关库的精化规格，都要按照官方示例配置。普通 GHC 编译成功与 LiquidHaskell 检查成功是不同的结果。
  4. 教程与依赖是否属于同一个时代。 引言中的操作流程有明确的历史背景，上游 README 也提示在线 HTML/PDF 可能落后于源码。旧接口、旧包版本或旧命令需要结合实际环境核对。

可先查看本机版本：

Shell
ghc --version
cabal --version
z3 --version

然后按官方安装说明和官方插件示例项目选择构建方案。本译本没有给出未经实测的「一条命令兼容所有版本」安装脚本，也没有重新声明某个历史组合是当前推荐环境。

原始示例在哪里？#

每章的「下载原始示例」链接提供上游 .lhs 文件。.lhs 是 literate Haskell，即把文字和程序写在同一文件里的格式。

这些文件用于对照和练习，不是一套已经补完答案、保证整体通过的现代工程模板。代码中可能有：

  • 演示验证失败的表达式；
  • 等待填写的规格、undefined 或 error；
  • 为聚焦某个概念而关闭的检查；
  • 不在网页正文中展示的导入、辅助定义或历史配置。

正文省略了上游明确标为隐藏的 comment 区块。完整原始文件仍保留这些内容，因此阅读片段与直接编译完整模块的行为可能不同。

怎样做一道练习#

建议把每道练习分成四步：

  1. 先用中文写下要证明的事。 例如：「索引不能小于 0，而且必须小于向量长度。」
  2. 指出哪些信息来自调用者。 这些通常对应前置条件；外部输入需要经过运行时校验才能满足它们。
  3. 写出函数答应提供的信息。 例如返回列表长度等于输入长度；这通常对应后置条件。
  4. 让验证器检查，再解释结果。 如果失败，区分实现错误、规格错误、缺少引理，以及工具暂时无法自动推导的事实。

不要用 assume 掩盖尚未解决的证明，也不要只为让检查变绿而删除目标性质。一个能通过的弱规格，可能没有表达你真正关心的事情。

原文中的练习题保留待完成状态。本译本没有把猜测的答案混入原代码。如果以后添加参考答案，应当放在独立位置，并说明验证过的工具链和命令。

怎样理解「验证通过」#

验证通过的意思是：在采用的模型、假设和输入前提下，工具接受了你写出的那些性质。 它不自动涵盖所有业务要求或运行环境故障。

阅读时要辨认的东西 它实际意味着什么
assume 把一个规格加入可信基础；不能据此说对应实现已经被证明
--no-termination 关闭终止性检查；一个可能不返回的函数不能因此被称为一定结束
数学整数模型 推理中的整数未必覆盖机器 Int 的溢出行为；参阅官方整数溢出说明
元素集合相等 说明出现过哪些不同元素；不记录每个元素重复了几次
指针的范围规格 只覆盖实际写出的内存模型与条件；不能自动替代底层实现、生命周期和其他未建模要求

因此，外部输入验证、集成测试、异常路径测试和规格审阅仍然各有职责。对于内部纯函数，可以用明确规格证明适合形式化的性质；是否减少已有测试，要根据性质覆盖和可信边界判断。

旧示例与当前 API#

教程用旧版 text / vector 接口展示：类型正确并不等于输入范围正确。这些示例的核心教学意义仍然清晰，但具体崩溃方式、返回字节和内部表示属于当时的实现背景。

例如 text 的内部编码后来发生过变化，详见其官方变更记录。本译本保留原输出作为历史材料，不把它描述成当前版本一定可以重现的漏洞。

网页使用小技巧#

  • 点击顶部搜索，或按 Ctrl+K / ⌘+K；没有在输入框中输入时，也可以按 /。
  • 搜索同时支持中文术语、英文术语和代码名称；多个关键词用空格分隔。
  • 按 Esc 关闭搜索，使用方向键在结果间移动。
  • 代码块右上角可以复制代码；浏览器拒绝剪贴板访问时会选中代码，供手动复制。
  • 页面会在当前浏览器记住最近阅读的章节，首页会显示「继续阅读」。此记录仅存于本地。
  • 浏览器的打印功能可导出当前页；打印样式会隐藏导航和操作按钮。
